# AI API Diagnostic Team — Implementation Plan (n8n)

> **For the executor:** This is a **navigation blueprint**, not code. Each task
> lists *where to go*, *what to create/configure*, and *how to verify*. Work the
> checkboxes in order. Build locally first, deploy at Task 10.

**Goal:** A conversational multi-agent "API Diagnostic Team" built low-code in
n8n, hosted on Render free + Supabase, traced in LangSmith, with a public chat
demo and a per-agent knowledge base.

**Architecture:** n8n Chat Trigger → Orchestrator AI Agent (session memory) →
specialist agents exposed as sub-workflow tools (HTTP Diagnostic, Authentication,
Root-Cause) → each with its own small KB. Supabase Postgres stores n8n data,
session memory, audit, and vectors. LangSmith traces every run.

**Tech stack:** n8n (self-hosted Community), Render (free web service), Supabase
(free Postgres + pgvector), Groq (LLM), Google Gemini embeddings, LangSmith.

**Spec:** `docs/superpowers/specs/2026-10-05-api-diagnostic-team-design.md`

## Global Constraints

- **Free tiers only.** LLM = Groq; embeddings = `gemini-embedding-001`; no OpenAI.
- **Never commit secrets.** Keys live in n8n credentials or host env vars;
  `.env.example` only in the repo.
- **Demo safety.** Public HTTP tool must block private/internal IPs; rate/budget
  caps on shared keys; editor owner-locked.
- **SUL compliance.** Free public demo, author owns credentials — allowed.
- **Fixed `N8N_ENCRYPTION_KEY`** on the host so credentials survive redeploys.
- **Session memory** keyed by Chat Trigger `sessionId`; new chat forgets; TTL cleanup.
- **One KB per agent**, markdown in the repo, embedded to pgvector.

## Review Focus

1. **SSRF via arbitrary URLs** — the HTTP tool must reject `localhost`, `10/8`,
   `172.16/12`, `192.168/16`, `169.254/16`, `::1`, and non-http(s) schemes.
2. **Shared free key abuse** — Groq/Gemini quotas can be exhausted by visitors;
   rate-limit + cap required before the demo is public.
3. **Memory leakage across sessions** — a wrong/missing `sessionId` binding would
   mix visitors' conversations; verify two chats stay isolated.
4. **Trace not found** — async LangSmith upload can make the trace URL 404 right
   after a run; set `LANGCHAIN_CALLBACKS_BACKGROUND=false` or add a wait.
5. **Supabase IPv4/pooler** — Render may not reach Supabase's direct (IPv6)
   endpoint; use the Session pooler string + SSL.

## Task 2: Supabase schema

**Where:** Supabase → SQL Editor.
**Produces:** tables for n8n-adjacent data, memory, audit, and the vector store.

- [ ] Run the KB vector table SQL:
```sql
create extension if not exists vector;
create table if not exists kb_chunks (
  id uuid primary key default gen_random_uuid(),
  agent text not null,
  content text,
  metadata jsonb,
  embedding vector(768)
);
```
- [ ] Create the **audit** table:
```sql
create table if not exists diagnostic_audit (
  id bigint generated by default as identity primary key,
  session_id text,
  request text,
  agents_used text,
  verdict text,
  confidence numeric,
  created_at timestamptz not null default now()
);
```
- [ ] Create the **session memory** table (n8n's Postgres Chat Memory can create
      its own, but pre-create to control schema):
```sql
create table if not exists chat_memory (
  id bigint generated by default as identity primary key,
  session_id text,
  message jsonb,
  created_at timestamptz not null default now()
);
create index if not exists chat_memory_session_idx on chat_memory (session_id);
```
- [ ] **Verify:** Table Editor shows `kb_chunks`, `diagnostic_audit`, `chat_memory`.
- [ ] **Copy the connection string:** Supabase → **Connect → Session pooler** →
      copy host/port/user/password (needed for n8n `DB_POSTGRESDB_*`). Use SSL.

## Task 5: Conversation core (chat + orchestrator + memory)

**Where:** n8n → new workflow `API Diagnostic Team`.
**Produces:** a working chat that remembers within a session and forgets on new chat.

- [ ] Add a **Chat Trigger** node. Enable **public** access; set title/subtitle
      ("AI API Diagnostic Team — demo"), welcome message, input placeholder.
- [ ] Add an **AI Agent** node connected to the trigger.
- [ ] Chat Model sub-node = the **Groq** model (e.g. `gpt-oss-120b`).
- [ ] Memory sub-node = **Postgres Chat Memory**, Session ID =
      `{{ $('Chat Trigger').item.json.sessionId }}`, window = last 10.
- [ ] System Message (Orchestrator persona, calm coordinator):
```
You are the coordinator of an API diagnostic team. Chat naturally. If the user
is just talking, answer directly. If they give a URL, error, or logs, decide
which specialists to involve and ask ONE clarifying question if needed.
Always end diagnostic replies with: what was checked, the likely cause, and
next steps. Never invent facts.
```
- [ ] **Verify memory:** open the chat URL → say "my name is Levi" → ask "what's
      my name?" → it answers Levi. Click **New chat** → ask again → it does not know.
- [ ] **Verify isolation:** open a second browser/profile → the second chat does
      not know the first session's name.

## Task 6: Agent — HTTP Diagnostic (single workflow, agent + HTTP tool)

**Where:** n8n → workflow `Agent — HTTP Diagnostic`.
**Produces:** an HTTP specialist **agent** that probes URLs.

**Nested-agent pattern (applies to EVERY specialist):** each specialist workflow
is itself an **AI Agent** with its own tools (and KB). The orchestrator calls the
specialist agent; the specialist agent calls its own tools.

- [ ] New workflow `Agent — HTTP Diagnostic` (folder `API Diagnostic Team`).
- [ ] **Execute Sub-workflow Trigger** input: `target` (string).
- [ ] **AI Agent** node (Groq), persona: terse, technical.
  - **Prompt** = `{{ $json.target }}`
  - **Tool:** **HTTP Request Tool** (the tool version of the HTTP node):
    - Method **GET**, **URL** = `{{ $fromAI('url', 'The public URL to fetch') }}`
    - **Response → Never Error** on; **Include Response Headers and Status** on
    - timeout `10000`; follow redirects (max `3`)
  - **System Message:**
```
You are the HTTP diagnostic specialist. Use the http_request tool to probe the
target — decide the URL yourself. Only fetch public http(s) URLs; NEVER private
addresses, localhost, or raw IP literals. Report status, redirects, content-type,
latency, and any anomaly (5xx, wrong content-type, redirect loop, timeout).
State the most likely issue. No fluff.
```
- [ ] (Task 9) attach its own **KB retriever** tool.
- [ ] **Register on the orchestrator:** Orchestrator → **Call n8n Workflow Tool**
      → `Agent — HTTP Diagnostic`.
  - **Description:** `HTTP specialist: probes a public URL and reports anomalies.`
  - **Workflow Inputs → `target`** = `{{ $fromAI('target', 'What to inspect: the URL or endpoint') }}`

**Verify:** chat "diagnose https://httpbin.org/status/500" → orchestrator calls
the HTTP agent → it uses `http_request` → reports 500.

> **Known trade-off (accepted):** a single-workflow agent can't host the SSRF
> guard, so this tool is *prompt-guarded only*. Mitigate with the rate limit in
> Task 14, and note the residual risk in the README's failure-modes section.

## Task 7: Authentication agent (evidence-based)

**Where:** n8n → new workflow `Agent — Authentication`.
**Produces:** an agent that diagnoses auth failures from pasted evidence —
**no credentials ever requested or stored**.

- [ ] **Execute Sub-workflow Trigger** inputs: `evidence` (string),
      `url` (string, optional).
- [ ] **AI Agent** node (persona: security-minded, precise).
  - **Prompt** = the pasted evidence (`{{ $json.evidence }}`).
  - **System Message:**
```
You are an authentication diagnostic specialist. You analyze pasted evidence
only — a failing HTTP response, its status, www-authenticate header, error body,
or the curl the user ran. Diagnose: 401 vs 403 vs 407, missing vs expired vs
wrong-scope token, wrong scheme. State the likely cause and the fix. NEVER ask
for or handle credentials/secrets.
```
- [ ] Optional branch: an **unauthenticated** HTTP Request (reuse the SSRF guard)
      to detect "auth required" (401) from a URL — but **never send credentials**.
- [ ] **(Task 9) attach its own KB retriever** tool — the authentication KB
      (`knowledge-base/authentication.md`), filtered to `agent = authentication`.
- [ ] Register as a **Call n8n Workflow Tool** on the orchestrator:
      *"Diagnose authentication failures from pasted evidence (status, headers,
      error body, curl). Inputs: evidence, optional url."*
- [ ] **Verify:** paste a sample 401 response (from a seeded target, Task 8) → it
      identifies the auth failure and a likely cause, without requesting a token.
